## 4. Smallest bounded adapter specification

1. Validate schema, operation/method, finite inputs, evidence/data fingerprints and bounds. Resolve only a compiled/reviewed profile authority; verify manifest/worker identities. Reject unsupported platform/profile without invoking a fallback.
2. Preserve private 0700/0600 exclusive run creation, fsync request and ordinal-1 consumption BEFORE any compute dispatch; preserve the SciPy unavailable/ambiguous-attempt terminal/replay semantics. Static malformed/untrusted authority may fail before admission as today. Tests must pin that distinction.
3. Authenticate the approved local engine endpoint/profile with an allowlisted environment; do not inherit `DOCKER_HOST`, `DOCKER_CONTEXT`, proxies, credentials, arbitrary config/plugins or user mounts. Verify the preloaded local image/config/platform and accepted in-image identities using bounded, no-pull operations. Missing image/daemon/qualification fails closed. Offline OCI import must preserve a verifiable digest-addressable reference; if the chosen store cannot, stop for contract review rather than invent a RepoDigest or push a registry.
4. Execute direct argv with `shell:false`, `--interactive`, no TTY, `--pull never`, exact platform and derived-image digest, `--network none`, read-only root, UID:GID 65532, no-new-privileges, all capabilities dropped, 1 CPU, 512 MiB memory/swap ceiling, 64 PIDs, 64 MiB noexec/nosuid/nodev tmpfs, no mounts/volumes/host PID/IPC/devices/ports. Reject image-declared volumes, unsafe config and unexpected writable paths. Preserve locale/TZ and one-thread BLAS settings in the qualified environment; no runtime dependency installation.
5. Bound stdin/stdout/stderr to existing 1,000,000-byte ceilings and compute to the existing ≤5-second deadline (default unchanged). Track an unambiguous attempt-bound container identity/CID. On overflow, timeout, crash or lost CLI connection, kill/remove ONLY that container and verify termination with separately bounded cleanup; killing the CLI is insufficient. Cleanup failure is terminal with explicit reconciliation-required evidence, never retry/prune or green acceptance. A preapproved qualified supervisor must enforce lifetime beyond parent loss; acceptance is blocked until that failure mode is proven.
6. Strictly validate method-specific finite output, expected worker/Python/dependency versions and request binding. Minimal explicit v2 result protocol: worker returns its exact finite canonical `resultJson` string plus SHA-256; host checks those bytes/hash, parses and verifies semantic equality to the typed result, and separately hashes the exact outer stdout bytes. This avoids treating JS reserialization as Python bytes. Version/review the worker and its new hash; do not change the current pinned worker now.
7. Persist v2 receipt/audit only after identity/output checks and successful lifecycle reconciliation; durable terminal failure otherwise. Retain privacy, no automatic retries and exclusive admission. Qualification is numerical/isolation authority only, never research approval.

`--interactive` and container-ID handling are documented by [Docker container run](https://docs.docker.com/reference/cli/docker/container/run/). Build attestations and their storage are described by [Docker attestations](https://docs.docker.com/build/metadata/attestations/) and [attestation storage](https://docs.docker.com/build/metadata/attestations/attestation-storage/); dependency attestation semantics by [PyPI](https://docs.pypi.org/attestations/). These documentation reads are not artifact, security or runtime qualification.
