# Stage 4B2D canonical read-only acceptance

Status: `REVIEW_REQUIRED`. This procedure is preparation only. It has not been executed against production.

## Trust boundary

Snapshot JSON, manifest hashes, environment variables, and callbacks supplied by the snapshot operator do not establish authority. The local runner accepts canonical authority only through a valid Ed25519-signed, redacted authority envelope whose public-key fingerprint has been separately reviewed and pinned in `STAGE4B2_APPROVED_OWNER_AUTHORITY_PUBLIC_KEY_SHA256`. That constant is intentionally `null`; therefore the repository currently cannot report a verified canonical admission.

The signing private key and all raw scripts/source documents stay outside Git. A later key fingerprint change requires separate owner authorization and code review. Never use a key generated by the snapshot-producing process as its own trust anchor.

## Separately authorized owner procedure

1. Obtain explicit authorization for one read-only production capture. Do not reuse any provider-trial authorization.
2. Through the existing authenticated owner/admin read path, capture the persisted project revision, canonical script bytes, ordered section IDs, 36 persisted scene IDs, 36 canonical scene references, and the existing 7/13/7 grounding graph into a private local snapshot. Do not reconstruct missing values.
3. A different trusted reviewer/process creates the detached baseline manifest from the independently captured persisted values and records its SHA-256 out of band.
4. Independently acquire each of the seven allowed original sources using the reviewed original-source acquisition contract. The prior arXiv smoke trial authorizes no additional canonical source. Record bounded acquisition provenance and document fingerprints without embedding raw documents in the authority envelope.
5. Independently review every claim/evidence relationship, contradiction, quantitative statement, causal inference, and unsupported assertion. Produce a complete five-section factual inventory with exact offsets and hashes. Review English clarity, narrative progression, precision, repetition, and word boundaries separately.
6. Independently capture the same persisted project revision, script fingerprint, and scene-identity fingerprint after the read-only review. Any mismatch blocks acceptance.
7. The trusted authority signer signs only the redacted baseline/source/review/before-after fingerprints. Verify and separately approve the public-key fingerprint before pinning it in reviewed code.
8. Place the private snapshot, manifest, signed envelope, and public key in owner-controlled local paths. Run the acceptance command once with:

   - `STAGE4B2_CANONICAL_SNAPSHOT_ACCEPTANCE=confirmed-read-only`
   - `STAGE4B2_CANONICAL_SNAPSHOT_PATH`
   - `STAGE4B2_CANONICAL_MANIFEST_PATH`
   - `STAGE4B2_CANONICAL_MANIFEST_SHA256`
   - `STAGE4B2_AUTHORITY_ENVELOPE_PATH`
   - `STAGE4B2_AUTHORITY_PUBLIC_KEY_PATH`

   and `node --experimental-strip-types scripts/stage-4b2-canonical-whole-script-acceptance.mjs`.

## Required redacted evidence

- Exact project/revision fingerprint and independently captured before/after fingerprints.
- Five ordered section identities, script revision 1, 480-second target.
- 36 persisted scene identities and 36 canonical references.
- Exact seven claims, 13 evidence identities and seven source identities bound to script grounding.
- Seven independently verified acquisition receipts and document fingerprints.
- Independent semantic-review receipt, complete factual-inventory receipt and editorial-review receipt.
- Signed authority envelope, separately approved public-key fingerprint, structured acceptance report.

If any item is missing, substituted, stale, self-attested or unverifiable, the result remains `REVIEW_REQUIRED` or `BLOCKED`. `closeStage4B2` remains false pending separate owner closure approval. Local input immutability is mechanical evidence only and does not prove production data was unchanged.
